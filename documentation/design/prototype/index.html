Autonomous coding. Accountable engineering.

An open-source, risk-aware workflow for AI coding agents. From requirements to verified pull requests, with independent reviews, traceable evidence and human control.

Writing the code is the fast part

Claude Code and Codex produce working changes in minutes. What they do not settle on their own is whether the change does what was asked, whether someone other than its author checked it, whether the checks ran on exactly that code, and who decided it may ship.

ACT is the workflow around the agents. It does not write code. It turns an approved plan into Issues, has one agent implement and an agent of another provider review, records the evidence for every acceptance criterion, and leaves the merge to you. Everything runs from your repository with shell scripts and plain files; there is no platform to host.

The agents

  • Write the code and the tests
  • Review a change, read-only
  • Propose what to do with each finding

ACT

  • Computes the risk level of each change
  • Picks the agent and model for the level
  • Refuses a review by the implementer's own provider
  • Commits only verified, reviewed, complete work

You

  • Approve the plan
  • Answer what the agents cannot decide
  • Approve protected changes
  • Merge

Plan once, then one line per feature

Every step on the workflow page.

A planning change, a new requirement or a changed roadmap, goes back through the plan review and your approval before features are built on it. Each feature runs step by step, with you approving the triage, or in one unattended command, run-feature.sh, which stops whenever it needs you.

Effort follows risk

Configured in risk.conf and agents.conf.

Each change gets a risk level, computed from what it touches, and each project picks a workflow profile. They are separate settings: the level describes the change, the profile describes how much ceremony the project wants for low and medium risk.

ACT enforces

  • The risk level, and that no agent lowers it
  • A reviewer of another provider than the implementer
  • Verification before review and before commit
  • A current review of the complete feature before commit
  • The completion gate and the triage rules
  • Read-only reviewers and sandboxed implementers
  • Rules read from the base branch, so a change cannot loosen its own checks

Your GitHub settings enforce

  • A ruleset on main that requires a pull request and the CI check
  • Code-owner review for protected paths
  • Who may bypass the rules
  • An approval the agent cannot give itself: needs a separate agent identity, not built yet

Learn from your runs

With report-runs.sh, show-experience.sh and analyze-runs.sh. The records in detail.

Every run leaves a record: the review rounds and their findings, what the triage decided, the checks that failed, why a run stopped, and the time and tokens of each step. After a number of features you ask a read-only analyst what keeps costing rounds, and it proposes what to change.

  • A finding needs two runs. One observation stays a hypothesis, and “not enough evidence” is a valid outcome.
  • Every conclusion cites its records, and says which differences in task size, model and workflow version it considered.
  • Nothing changes by itself. Each proposal names its place, and you take it through the review and approval there.
  • Repeatable, and nothing counted twice. Each analysis keeps its input and sources; evidence an earlier analysis used is marked as such.

ACT ran it on itself on 28 October 2026: 41 runs of 19 features. Among the findings: in five runs the reviewer raised a fixed finding again as unresolved; six of seven failed runs recorded no reason for the stop; the self-test suite had grown from 463 s to 915 s in two days. Start a project

The full getting-started guide.

# a new repository from the template
$ gh repo create my-project --template taspinar/agentic-coding-template --private --clone
$ cd my-project
$ ./scripts/doctor.sh
# plan once: requirements, architecture, roadmap; you approve
$ ./scripts/start-planning.sh --description idea.md
# then each feature, from Issue to pull request
$ ./scripts/create-feature-issue.sh F01
$ ./scripts/run-feature.sh 1

You need Git, the GitHub CLI, jq, Claude Code and Codex: as shipped, Claude implements and Codex reviews, and a review by the implementer's own provider is refused. doctor.sh checks all of it, including the Codex sandbox and your Git identity.
