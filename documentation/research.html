Research and comparisons

The template was not designed in isolation. Between September and October 2026 it was compared with the larger frameworks for agentic development, with collections of agent skills, and with ideas from practitioners. This page records what was adapted, what was left out on purpose, and what is still only a proposal.

"Adapted from" means an idea that was compared and reworked to fit this workflow. No code was copied from the projects named here, and a similar feature may have more than one origin.

Each row carries one of four labels:

Built works in the template today · Principle guides the design, built to a varying degree · Proposed a candidate, not built · Left out deliberately not part of the workflow

The guiding idea

One small, model-agnostic, auditable delivery workflow, not a stack of competing frameworks. Product decisions and risky changes have human gates; agents implement and review independently; checks and stored records provide the evidence; GitHub is where the work is coordinated. Every comparison below was read with one question: does this idea make that workflow better, or does it add a second system beside it?

Specialist skills and audits

A survey of twenty public collections of agent skills (security, front end, cloud providers, evaluation of language models, design) led to one decision: a project picks the few skills its work needs. The template bundles none of them.

What use taught

Not everything came from reading. Three subjects were worked out on the template and the project built with it.

Keeping projects up to date

A repository made from a GitHub template does not receive later changes of that template. Subtrees, submodules, and cherry-picking were compared; the choice was an explicit script. sync-template.sh takes over only the paths that belong to the template and leaves the project's own files alone. Built

Reviews and approvals that stay true

A review is bound to the content it read and goes stale when that changes. An approval of the planning is bound to the documents by a fingerprint. A feature is reviewed against the base it was created from, also when that base has moved on. An agent that ends "blocked" counts as blocked only when it left a question for a person. Built

The cost of verification

On the project built with the template, CI grew from about one minute to more than fifteen as browser checks, site builds, and determinism checks were added. A passed verification is now reused for identical content, and the template's own tests run locally only when the workflow changed. Selecting checks by what a change can affect, caching, and budgets for the duration of a check are Proposed. Removing useful checks to save time was Left out.
