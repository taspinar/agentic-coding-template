Agentic Coding Template

A GitHub repository template for building software with AI coding agents.

Plan projects, implement features, review code independently, and verify changes with a repeatable workflow. You choose which agents and models do the work, and you keep the important decisions.

It works with Claude Code and Codex, and with any programming language or framework.

How it works

  1. 1. Plan

    Clarify the requirements, define the architecture, and approve a roadmap.

    You approve the plan

  2. 2. Build

    An AI agent implements a feature in its own Git branch and worktree.

  3. 3. Verify and review

    Run the checks, review the change independently, and address the findings.

  4. 4. Deliver

    Open a pull request with the recorded verification and review evidence.

    An authorized maintainer merges

Each feature goes through build, review, and delivery. The project plan can be updated when requirements change.

Agents handle much of the development work. You stay in control of requirements, important approvals, and how changes are merged.

What's inside the template

The template gives you a ready-to-use repository structure for working with AI coding agents.

It includes instructions for agents, configurable roles and models, scripts for planning and development, independent code reviews, and automated verification.

Everything runs from your own repository, without a separate orchestration platform.

Why use it

Clear requirements

A round of questions and your approval come before any plan, so agents work toward a goal you agreed to.

Independent reviews

A separate, read-only agent reviews every change, which gives you a second perspective on the code.

Meaningful verification

One command runs your project's checks and records what was checked. If the code changes, the checks run again.

Traceable changes

Planning, GitHub issues, review decisions, and pull requests stay connected, so you can see why a change was made.

How the workflow flags risky changes, and what you configure in GitHub to enforce approvals, is in Configuration and security.

What the template does not try to do

  • No central orchestration platform is required. You can use the template on your own machine with one coding agent.
  • A feature becomes an issue when you are ready to build it. The roadmap is not converted into a GitHub backlog in advance.
  • Testing follows what the change needs. The template does not require test-driven development for every edit.
  • Unattended execution stops at a pull request. run-feature.sh does not merge or deploy.
  • Git worktrees are not sandboxes. They separate working files, not databases, services, credentials, or network resources.
