Agentic Coding Template

A GitHub repository template for building software with AI coding agents.

It gives you a structured workflow for planning a project, implementing features, reviewing code, and verifying changes. Agents do much of the development work. You stay in control of the requirements, the important decisions, and the approvals.

The template works with Claude Code and Codex, and with any programming language or framework.

What the template includes

The template provides Bash scripts, instructions for agents, and configuration files that you reuse in your own GitHub repositories. It uses Git and GitHub to organize the work, and you choose which AI agent and model does the planning, the implementation, and the review.

To get started you need Git, the GitHub CLI, jq, and at least one supported coding agent.

How it works

You approve the plan

An agent helps turn your idea into requirements, an architecture, and a roadmap. You review and approve them before feature development begins.

Agents implement and review separately

Each feature gets its own Git branch and worktree, a separate working copy of the repository. One agent implements the change; an independent, read-only agent reviews it.

Tests and reviews are recorded

The workflow runs the project's checks and records what was tested and reviewed. If the code changes afterward, the earlier results are no longer valid, and the scripts ask for them again.

Changes are tracked in GitHub

Each feature has a GitHub issue and a pull request. The code, the decisions, the review findings, and the verification results stay together.

You stay in control of important changes

The workflow flags changes that need extra approval, such as changes to protected files or architecture decisions. To enforce those approvals on GitHub, you also configure repository permissions and branch protection.

Why we built it

AI coding agents can do more than write single pieces of code. They can help plan a project, implement features, write tests, and review changes. Using them across a whole development process raises new questions. How do you keep the requirements consistent? How do you know a change was really reviewed and tested? How do you let agents work on their own without giving up the important decisions?

None of the answers are new. The template brings established software engineering practices together with AI coding tools: planning before building, independent review, automated verification, a Git-based process, and human approval for decisions that matter. Three lessons from using it shaped the result:

  • Unclear goals cost more than slow code. Asking questions about an idea before anything is designed removed most of the later rework. That is why every plan starts with a clarification step and an approval.
  • An agent that checks its own work finds little. A separate reviewer that cannot edit the code, an explicit decision for every finding, and a second review after the fixes caught most of the real problems.
  • An agent should not judge its own risk. Whether a change needs the owner's approval is decided first by rules about the files it touches. The reviewer's judgment comes on top and can only make the outcome stricter.

The template keeps changing as it is used. Each time a run was interrupted, a review turned out to be outdated, or a requirement changed halfway, the scripts gained a safeguard for that situation.

What the template does not try to do

The goal is a reliable development workflow without a large platform or a stack of separate frameworks.

  • No central orchestration platform is required. You can use the template on your own machine with one coding agent.
  • A feature becomes an issue when you are ready to build it. The roadmap is not converted into a GitHub backlog in advance.
  • Testing follows what the change needs. The template does not require test-driven development for every edit.
  • Unattended execution stops at a pull request. run-feature.sh does not merge or deploy.
  • Git worktrees are not sandboxes. They separate working files, not databases, services, credentials, or network resources.
