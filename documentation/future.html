Possible improvements

We keep exploring ways to improve the template. The ideas below cover security, planning, testing, agent isolation, and support for larger teams.

This is not a committed roadmap. A new feature has to add clear value without making the template harder to use for a single developer.

Partially available means related functionality already exists. Under consideration means the idea was discussed and is not built.

Security and approvals

ImprovementWhat it would addStatus
GitHub approval rulesCode owners and repository rules, so that protected files and important changes need the right approvalsPartially available the scripts classify a change; GitHub does not enforce the approvals yet
Separate agent identitiesGitHub identities with limited permissions for coding agents, in place of the owner's permissionsUnder consideration
More thorough reviews for risky changesAdditional checks for changes to security, infrastructure, or important architecture decisionsPartially available risk classification exists; specialized reviews do not

Planning and task execution

ImprovementWhat it would addStatus
Feature clarificationFocused questions when a feature issue lacks important detailsUnder consideration
Dependency-aware planningDependencies between tasks and features in a form that automation can usePartially available the roadmap describes dependencies in words
Ready-to-run task queueA list of the tasks whose dependencies are complete and that an agent can startUnder consideration
Parallel executionSeveral agents working on separate features without conflictsUnder consideration separate worktrees already allow concurrent work that you start yourself
Better failure recoveryDiagnosing common failures and recovering without redoing finished workPartially available retries and resuming are supported

Reviews, testing, and quality

ImprovementWhat it would addStatus
Two independent reviewersOne review of the behavior and one of the engineering qualityUnder consideration
Faster, more selective CIRunning the tests a change affects, not everything every timeUnder consideration a successful verification is already reused for unchanged content
Requirements-to-test trackingWhich implementation and which tests provide the evidence for each requirementUnder consideration
Browser-based validationBrowser tests with screenshots or traces for user-interface changesUnder consideration a project can configure its own browser tests
Specialized quality checksSecurity, performance, API, or infrastructure checks where they are relevantUnder consideration

Agent environments and infrastructure

ImprovementWhat it would addStatus
Full environment isolationFor each agent its own database, cache, services, queues, ports, credentials, and working filesUnder consideration only the working files are separated today
Containers or virtual machines per taskAn isolated environment that is created when work starts and removed afterwardUnder consideration
Reproducible database copiesA separate development database with safe, sanitized test data for each agentUnder consideration
Remote executionAgent runs that continue on a server when the developer's laptop is closedUnder consideration

Skills and model selection

ImprovementWhat it would addStatus
Reusable skills registrySelecting, versioning, and managing specialist agent skills per project and roleUnder consideration
Dynamic model selectionChoosing an AI model by what a task needs and what it costsUnder consideration a model is already configured per role and can be set per run

Run analyticsDuration, retries, model usage, and cost of runsUnder consideration each run already keeps a log
