Possible improvements

Enhancements the template could get, drawn from the research into existing frameworks, agentic workflows, and software factories, and from running it on a real project.

These are candidates, not commitments. A feature that is added should stay modular and optional, and the template has to keep working for one developer with one laptop.

The third column says where the template stands today. Nothing on this page is promised for a date.

Security and governance

ImprovementWhat it would doToday
GitHub governanceEnforce protected files, code owners, and role-based approvals for decision records, roadmaps, scripts, and infrastructure.Partly built The merge gate classifies protected and sensitive paths today; code owners and review thresholds enforced by GitHub are not set up.
Agent identity isolationGive agents separate GitHub identities and restricted permissions.Proposed While an agent runs with the owner's permissions, a script cannot enforce a separation of duties by itself.
Risk-based approval gatesRequire stronger reviews for security-sensitive or architectural changes.Partly built A change of a decision record, of a protected path, or with a major impact waits for the owner; reviews by a specialist per kind of risk do not exist.

Planning and orchestration

ImprovementWhat it would doToday
Feature clarification gateResolve unclear requirements before implementation begins.Proposed The planning is questioned at the start; a single feature is not.
Dependency-aware planningTrack dependencies between features and implementation tasks.Partly built The roadmap names the dependencies of a feature in words; nothing reads them.
Ready queueAutomatically identify tasks that are ready for execution.Proposed
Parallel agent orchestrationExecute independent tasks concurrently while preventing conflicts.Proposed Features can run side by side in their own worktrees today, started by hand; two features that write the same module still collide at the merge.
Automated failure recoveryDiagnose failed agent runs and apply controlled recovery strategies.Partly built run-feature.sh retries what looks temporary and lets the implementer repair a failing verification; it does not diagnose a failure caused by a base branch that moved on.

Quality and testing

ImprovementWhat it would doToday
Dual independent reviewUse separate reviewers for functional correctness and engineering quality.Proposed
Selective CI and test impact analysisRun relevant tests based on changed code and dependencies.Proposed A passed verification is reused for identical content; checks are not selected by impact.
Requirements traceabilityLink requirements to implementations, tests, and verification evidence.Proposed
Browser-based validationValidate user interface features with Playwright, screenshots, and browser traces.Proposed Left to the checks of a project today.
Specialized quality gatesAdd targeted security, performance, API, and infrastructure reviews.Proposed

Agent isolation and infrastructure

ImprovementWhat it would doToday
Full environment isolation per agentGive each agent its own worktree, database, cache, services, queues, ports, and runtime.Proposed A worktree separates files only.
Container or virtual machine provisioningCreate and destroy isolated environments per task.Proposed
Database cloning and seedingProvision reproducible, sanitized database copies for independent agent development.Proposed
Remote agent executionRun agents on a dedicated server, independent of a developer's laptop.Proposed An unattended run stops today when the laptop sleeps or loses its network.

Skills and intelligence

ImprovementWhat it would doToday
Agent skills registryManage reusable, versioned skills with role-based access and configuration per project.Proposed
Dynamic model routingSelect a model by the complexity, the needs, and the cost of a task.Proposed The agent and model of each role are configured per project and can be set per run.
Continuous workflow improvementLearn from recurring failures and propose improvements to prompts, tests, and skills.Proposed A place for lessons exists; nothing fills it from the reviews.
Agent run analyticsTrack execution time, retries, model usage, costs, and success rates.Proposed A run keeps a log of its steps and interruptions; nothing aggregates it.
